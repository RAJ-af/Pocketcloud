# Known limitations and unverified work

1. **Flutter build still unverified in this environment.** The source has been patched for the observed file_picker v13 API errors, updated share_plus usage, transfer authorization typing, and host-listener reattachment. Flutter/Dart SDK is not installed here and network access to download it is unavailable, so no compile, analyzer or Flutter test command could be run locally. Run the included GitHub Actions workflow and fix any SDK-reported issues before trusting the build.
2. **Live backend pending.** A new Supabase project has not been created or configured. Migration, Edge Functions and Security/Performance Advisors need live verification after the destination organization is confirmed.
3. **Remote WebRTC source is not device-verified.** Offer/answer/ICE, data-channel transfer, permissions, SHA-256 and bounded reconnect are implemented in source, but have not been run on two physical devices. The flutter_webrtc APIs and cross-network behavior require a real build and tests.
4. **TURN service is not supplied.** STUN-only direct connectivity cannot cross every restrictive NAT, office Wi-Fi or carrier network. Add and operate a TURN relay for broader reachability; that may incur separate cost.
5. **No Android foreground service.** The server listener lives in the Flutter process. Keep the app open for this MVP. Screen-off, Doze, OEM battery limits, reboot and force-stop behavior are not solved. Force-stop or power loss stops the server.
6. **Only one active peer per server instance.** A server can store more than one pair but the first prototype is not designed or load-tested for concurrent peers.
7. **Scoped file access only.** The app exposes files explicitly imported into its own app-private vault. It cannot read other applications' private folders or control the whole operating system.
8. **MVP transfer constraints.** Files are limited to 25 MiB per transfer; transfers are sequential and a large vault may make listing slow. Interrupted-transfer cleanup, disk-full and severe memory pressure require physical-device testing. Received files are staged to a temporary file before rename so failed writes should not appear as completed files.
9. **No additional vault encryption layer.** App-private storage relies on Android/device storage protection; no separate app-layer encryption key or encrypted vault format is provided.
10. **Operational hardening incomplete.** Automatic signalling cleanup, fixed retention periods, rate limits, abuse detection, self-service account deletion, telemetry/alerting, external penetration testing and security audit remain future work.
11. **Legal drafts need completion.** Add operator identity/contact details and obtain jurisdiction-specific review for Terms, privacy, age restrictions, user rights and account deletion.
12. **Dependency lockfile.** The Flutter SDK is unavailable here, so `pubspec.lock` could not be generated. After the first successful CI `flutter pub get`, review and commit `pubspec.lock` to make subsequent builds reproducible.
